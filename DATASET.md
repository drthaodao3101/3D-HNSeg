# 3D-HNSeg Dataset

`3D-HNSeg` is a 3D head-and-neck CT segmentation dataset used to train and evaluate the TD-Mamba model in this repository. It contains **204 contrast CT volumes** with voxel-wise annotations of three head-and-neck lesion types: **abscess**, **tumor**, and **cyst**.

## 1. Data access

The dataset documentation and source code are available at the project repository:

**https://github.com/drthaodao3101/3D-HNSeg**

The repository provides directory organization and file-format descriptions, label definitions, the fixed cross-validation split manifest, preprocessing/normalization procedures, and licensing/terms of use for the released code and documentation (see below, and README.md for environment setup and training/inference/evaluation commands).

The raw CT volumes and annotation masks are clinical data collected from **Thống Nhất Hospital** and contain protected patient information; they are **not redistributed directly in this repository**. Access to the de-identified imaging data is available on reasonable request for research purposes, in accordance with the applicable institutional and ethical data-sharing requirements — please contact the maintainer.

## 2. Cohort summary

| Item | Value |
|---|---|
| Total annotated cases (CT studies) | 204 |
| Unique patients | 188 |
| Patients with more than one study | 15 (2 examinations each, distinguished by exam date) |
| Total annotated lesions | 241 (179 tumor, 38 cyst, 24 abscess) |
| Volumes with multiple lesions | 26 (8 with lesions from more than one category) |
| Modality | Contrast-enhanced head & neck CT |
| Original in-plane size | 512 × 512 (variable slice count, see below) |
| Original spacing (median, mm) | ≈ 0.45–1.0 (in-plane), ≈ 0.45–1.0 (axial), case-dependent |
| Label classes | background, abscess, tumor, cyst |
| Split protocol | 5-fold cross-validation, constructed at the CT-volume level (see Section 7) |

Some patients underwent CT imaging on more than one date (e.g. follow-up or recurrence). Each study is treated as an **independent case** and identified by `<patient_id>` for a single study, or `<patient_id>_<DDMMYY>` when multiple studies exist for the same patient, e.g.:

```
13048018_100619   # patient 13048018, study on 10-06-19
13048018_130919   # patient 13048018, study on 13-09-19
```

## 3. Label definitions

Segmentation masks are single-channel volumes with integer voxel labels:

| Value | Class | Description |
|---|---|---|
| 0 | background | Everything outside the three lesion classes |
| 1 | abscess | Abscess / infected fluid collection |
| 2 | tumor | Tumor / neoplastic mass |
| 3 | cyst | Cystic lesion |

This mapping is stored in `data/henect204_seg/dataset.json` under `"labels"` and is used directly by the loss (`DiceCELoss`, `to_onehot_y=True`) and the evaluation code (`3_compute_metrics.py`, `3_compute_metrics_folds.py`).

## 4. Directory layout

The dataset directory follows an nnU-Net-style layout, rooted at `data/henect204_seg/`:

```
data/henect204_seg/
├── dataset.json                 # dataset metadata: labels, channel names, image/label file list
├── dataset_fingerprint.json     # per-case spacing/shape/intensity statistics (used for planning/normalization)
├── splits_final.json            # list of 5 {train, val} case-id folds used for training
├── splits_fold0.json ... splits_fold4.json   # single-fold copies of the same split (convenience files)
├── imagesTr/                    # raw CT volumes, one .nrrd per case: "<case_id>_0000.nrrd"
├── labelsTr/                    # raw voxel-wise label volumes: "<case_id>.nrrd"
├── gt_segmentations/            # full-resolution ground-truth masks used for final metric computation
│   └── <case_id>.nrrd
└── Plans_3d_lowres/              # preprocessed training data (cropped, resampled, normalized)
    ├── <case_id>.pkl             # per-case properties (spacing, cropping bbox, shape, class locations, ...)
    ├── <case_id>.b2nd            # preprocessed image volume (Blosc2 NDArray, C×D×H×W)
    └── <case_id>_seg.b2nd        # preprocessed label volume (Blosc2 NDArray)
```

Notes:
- `imagesTr/` and `labelsTr/` hold the **raw, unprocessed** CT/label pairs referenced by `dataset.json`. They are the input to the preprocessing step.
- `gt_segmentations/` holds the label volumes at their **original resolution/spacing** and is used only at evaluation time (`2_predict.py`, `3_compute_metrics*.py`) so that Dice/IoU/HD95 are computed against the true clinical resolution rather than the resampled training resolution.
- `Plans_3d_lowres/` is generated by the preprocessing pipeline (`light_training/preprocessing/preprocessors/default_preprocessor.py`) and is what the `Dataset` classes in `light_training/dataloading/dataset.py` actually read during training (`MedicalDataset`) and validation (`MedicalDataset_ForValidation`).

## 5. File formats

- **Volumes/masks**: [NRRD](http://teem.sourceforge.net/nrrd/format.html) (`.nrrd`), read/written with `SimpleITK`.
- **Preprocessed tensors**: [Blosc2 NDArray](https://www.blosc.org/python-blosc2/) (`.b2nd`), a compressed chunked array format used to keep the cropped/resampled volumes fast to load during training. Image tensors are stored as `C×D×H×W` (`C=1` channel: CT).
- **Case properties**: Python `pickle` (`.pkl`) storing a dict per case with:
  - `sitk_stuff`: original SimpleITK `spacing`, `origin`, `direction` (needed to write predictions back to the original geometry)
  - `spacing`: voxel spacing after preprocessing
  - `shape_before_cropping`, `bbox_used_for_cropping`, `shape_after_cropping_and_before_resampling`
  - `class_locations`: foreground voxel coordinates per class, used for foreground oversampling during patch sampling

## 6. Preprocessing pipeline

Preprocessing follows the nnU-Net v2 recipe (adapted in `light_training/preprocessing/`):

1. **Crop to non-zero region** (`light_training/preprocessing/cropping/cropping.py`) — removes the empty air/background border around the patient.
2. **Resample** image and label to a common low-resolution target spacing (`light_training/preprocessing/resampling/default_resampling.py`), computed from the dataset's spacing distribution (see `dataset_fingerprint.json → spacings`). Images are resampled with third-order spline interpolation, labels with nearest-neighbour interpolation.
3. **Intensity normalization** with `CTNormalization` (`light_training/preprocessing/normalization/default_normalization_schemes.py`): voxel values are clipped to the dataset's `[percentile_00_5, percentile_99_5]` HU range and z-scored using the foreground `mean`/`std` recorded in `dataset_fingerprint.json` (min = -1024, max = 1766, mean ≈ 59.7, std ≈ 52.9 HU over the whole cohort, computed on foreground voxels).
4. **Serialize** each case to `Plans_3d_lowres/<case_id>.b2nd` / `<case_id>_seg.b2nd` plus its `.pkl` properties file.

The dataset fingerprint (`dataset_fingerprint.json`) is computed once over all 204 training cases and is what drives step 2–3 above (target spacing, normalization statistics).

## 7. Train / validation split

`splits_final.json` contains a list of 5 folds, each a `{"train": [...], "val": [...]}` dict of case IDs (204 cases total, split at the CT-volume level):

| Fold | #Train | #Val |
|---|---|---|
| 0 | 163 | 41 |
| 1 | 163 | 41 |
| 2 | 163 | 41 |
| 3 | 163 | 41 |
| 4 | 164 | 40 |

- During **training** (`1_train.py`), `get_train_val_loader_from_json` reads the requested fold from `splits_final.json` and loads the corresponding preprocessed `Plans_3d_lowres` tensors for both train and validation.
- During **inference/metrics** (`2_predict.py`, `3_compute_metrics.py`), the validation set of each fold is used, and ground truth is read from `gt_segmentations/` at full resolution rather than the resampled training tensors.
- `3_compute_metrics.py` aggregates the validation set of **all 5 folds** (`get_train_val_loader_from_json_for_cross_validation`) to report metrics over the full 204-case cohort under 5-fold cross-validation.

There is currently **no held-out test set** (`numTest: 0` in `dataset.json`); model selection and reporting are done purely via 5-fold cross-validation on the 204 cases.

**Note on patient-level grouping**: folds were constructed to maintain a reasonably balanced distribution of lesion categories (tumor/cyst/abscess) across partitions. Because 15 patients contributed studies at more than one time point (Section 2), a small number of patients have studies split across different folds — the current partitioning is therefore **not strictly patient-level**. This should be considered when interpreting cross-fold generalization.

## 8. Preparing your own data in this format

To train this pipeline on a new dataset:

1. Convert volumes/masks to `.nrrd` and place them under `imagesTr/<case_id>_0000.nrrd` and `labelsTr/<case_id>.nrrd`, and duplicate the full-resolution masks into `gt_segmentations/<case_id>.nrrd`.
2. Write a `dataset.json` following the same schema (channel names, `labels`, `numTraining`, `training` list of image/label pairs).
3. Run the preprocessing pipeline (`light_training/preprocessing/preprocessors/default_preprocessor.py`) to produce `dataset_fingerprint.json` and `Plans_3d_lowres/`.
4. Generate a `splits_final.json` with your desired K-fold split (grouped by patient if a patient can contribute more than one study).

See [README.md](README.md) for the corresponding training/inference/evaluation commands.
